# Delegate reversible Setup authoring defaults

Status: accepted process decision D60; governs remaining first-episode authoring inside locked boundaries

The first episode will use one named, versioned Authoring Default profile instead of returning every reversible fictional label, clock, field, value, report phrase, and serialization choice for owner ratification. The author chooses the coherent recommended default, records it before outputs, and changes it by profile version and hash until the run freezes.

## Considered options

- Continue field-by-field owner selection for all Setup details.
- Let implementation choose unrecorded values as needed.
- Use one documented, reversible default profile with explicit owner-level stop conditions.

Field-by-field selection preserves direct control but consumes the schedule and makes minor values look like scientific decisions. Unrecorded implementation defaults move faster but destroy provenance and allow code convenience to change the experiment. A versioned profile preserves speed, replay identity, and later revision without confusing authored detail with a locked evaluation choice.

## Consequences

Synthetic IDs, map labels, exact times, bounded values, consistent report wording, deterministic serialization, abort codes, one bounded Seed, and provisional probe or projection fields may be authored without another question. They remain provisional until frozen and must respect every locked World, Setup, Charter, and evaluation rule.

Changes to the conflict, Focal Room, actor intent or doctrine, Charter authority or institutional identity, open-versus-closed World contract, matching or evaluation target, public claim, publication, external cost, destructive work, or material scope still require an explicit owner decision. Recommended Charter details may be drafted as one bundle, but ratification remains a batch gate rather than a sequence of microquestions.

The initial profile is specification module 13. Before freeze it may change with a new version and recorded rationale. After any model output exists, a bound value cannot change in place; the appropriate Setup, profile, World, Charter, or run identity must change and the comparison must be rerun. This ADR authorizes documentation of defaults, not implementation, experiments, Packet rewrite, publication, submission, or push.
